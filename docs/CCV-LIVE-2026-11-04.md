# Live ordering approval and route

Scott explicitly confirmed merchant approval on 4 November 2026 and requested activation, publication and a simple checkout UX. This supersedes the earlier approval-pending operating instruction.

The active endpoint is `ssk-commerce-v15`, revision `ccv-r03-01`. Public ordering uses the strict server flag `CCV_LIVE_ORDERING_V15_ENABLED=true`. Keep `CCV_ACCEPTANCE_V15_TESTS_ENABLED`, both v14 switches and both unversioned legacy switches false. Credentials remain in the existing `CCV_SHOP_*` secret namespace. Old handlers must never be activated to restore compatibility.

V14 continued returning its previous revision and disabled runtime after a successful settings update and redeployment. V15 provides a separate execution pin; verify the returned revision and `checkoutEnabled`, rather than trusting deployment success. The reviewed canonical store, service, CCV adapter and contract modules are identical between v14 and v15.

Customer route: configure, confirm choices, save the fixed design, review the order, continue to SSK's CCV checkout, enter delivery details and select payment. The bottom review action opens saving/checkout. Shared links create a separate checkout capability for the recipient. Same-page order-fragment navigation reloads the snapshot. Six gloves maximum, one CCV row/specification per glove. Prices and shipping remain server verified.

The product-page Google Form entry was replaced with a red configurator link after retaining its original HTML locally. Only the product description was patched; price, stock, product photos and delivery settings were preserved. CCV normalizes HTML/entity serialization, so comparison uses preserved content and destination, not raw description string equality.

Activation acceptance uses synthetic unpaid, incomplete baskets only. No customer identity, terms acceptance, completed purchase or money transfer is part of these checks. Actual payment settlement, confirmation email delivery and the CCV payment-return experience require a real transaction and remain unverified. Do not describe those as tested.

To pause, set only `CCV_LIVE_ORDERING_V15_ENABLED=false`, and verify public config and checkout rejection. Previously issued CCV URLs are independent capabilities and must be invalidated in CCV separately if necessary. Do not publish checkout URLs or capability tokens in repository evidence.
